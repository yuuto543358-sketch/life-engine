# LIFE ENGINE — VERDANTH（ヴェルダンス）

**あなたの人生は、ひとつの世界になる。**

時間・お金・目標・日々の記録を、自然と文明が共存するひとつの世界として表す iPhone 向けの Web アプリです。実際の記録が森や道や建物になり、「この選択をしたらどうなるか」を計算で試せます。

> 「VERDANTH」は仮の名前です。公開する前に、商標や名前が使えるかを確認してください。

## 世界のしくみ（すべて決まったルールで計算。AI は使いません）

| 領域 | 意味 | 何で変わるか |
|---|---|---|
| 原生域（遠くの山と霧） | まだ知らない自分 | 計画も記録もない領域の割合で霧が深くなる。まだ歩き出していない開拓計画は旗になる |
| 自然域（森・川・水辺） | 日々の暮らし | 睡眠・家事・その他の記録をした日数で森が広がる。静寂の地の記録で花、何もしない時間で蛍 |
| 道と集落 | 行動と経験 | 足跡（記録）を残した日数で道がのびる。登録したつながりが橋になる |
| 文明域（建物・記念碑） | 築いたもの | 領域ごとの記録の累計時間で拠点が育つ。蓄えの蔵は貯金が生活費の何か月分か。達成した目標と節目は記念碑 |

- **休息の法則**: 世界は記録の積み重ねだけで育つため、休んだ日に何かが減ることはありません。
- **記憶の法則**: 達成した目標を消しても、記念碑は年代記に残ります。
- 同じデータなら必ず同じ世界になります。健康や仕事の良し悪しは判定しません。
- ルールの本体: `src/engine/world.ts`（テスト: `src/engine/world.test.ts`）。絵は `src/world/` で、エンジンの結果だけを見て描きます。

## 5つの場所

| 場所 | 中身 |
|---|---|
| 世界の中心 | 風景・今日の足跡・次の一歩・進行中の開拓計画・最近の世界の変化・世界のようす |
| 世界地図 | 領域を古地図として表示。つながり図（目標どうしの関係）も |
| 開拓の間 | 時間・お金・開拓計画（目標）のシミュレーションとシナリオ比較 |
| 年代記の館 | 旅の記録（写真付き日記）・節目・足跡・世界の変化を時間順に。足跡と観測（計画と実績の差）も |
| 静寂の地 | 自由に書く・ふりかえり・明日の準備・何もしない時間 |

設定（世界の調律）は、世界の中心の右上の歯車から開きます。

- **AI は使いません。** すべての結果は決まった計算式で出します。同じ入力なら必ず同じ結果になります。
- **データはあなたの端末の中だけ**（ブラウザの IndexedDB）に保存されます。サーバーへの送信やアカウント登録はありません。
- **オフラインでも動きます**（PWA）。ホーム画面に追加するとアプリのように使えます。

| 画面 | 内容 |

## iPhone で使う方法（いちばんかんたん）

GitHub Pages という無料の公開機能を使います。最初に1回だけ設定が必要です。

1. パソコンかスマホのブラウザで、このリポジトリの GitHub ページを開きます。
2. 上のメニューの **Settings（設定）** を押します。
3. 左のメニューから **Pages** を押します。
4. 「Build and deployment」の **Source** を **GitHub Actions** にします。
5. 上のメニューの **Actions** を押し、「Deploy to GitHub Pages」が緑のチェックになるまで数分待ちます（まだ動いていなければ「Run workflow」を押します）。
6. 終わると `https://（あなたのユーザー名）.github.io/life-engine/` でアプリが開けます。
7. iPhone の **Safari** でそのアドレスを開き、下の「共有」ボタン →「**ホーム画面に追加**」を押すと、アプリのように使えます。

> 注意: データはその iPhone の中だけに保存されます。機種変更の前や、ときどき「設定 → データを書き出す」でバックアップを保存してください。

## パソコンで動かす方法（開発者向け）

[Node.js](https://nodejs.org/)（バージョン 20 以上）が必要です。

```bash
npm install        # 必要な部品をダウンロード（最初の1回だけ）
npm run dev        # 開発用サーバーを起動 → 表示された http://localhost:5173 を開く
npm test           # 計算ロジックのテストを実行
npm run build      # 公開用のファイルを dist/ に作る
npm run preview    # 作ったファイルを確認する
```

同じ Wi-Fi の iPhone から確認するときは、`npm run dev` で表示される `Network:` のアドレスを Safari で開きます。

## 計算のルール

- 週間時間 = 1日あたりの時間 × 週の日数。自由時間 = 1週間の総時間（通常168時間）− 配分済みの時間
- 目標の時間は、指定した枠（勉強など）から使い、枠を超えた分だけ自由時間から使う（二重に数えない）
- 時間と予算は、**あなたが決めた優先順位の順**に割り当てる。アプリが優先順位を決めることはない
- 月間収支 = 手取り収入 − 固定費 − 変動費。実際に貯金できる額 = 毎月の貯金額と月間収支の小さいほう
- 目標の毎月の予算 =（予算 − 記録した支出）÷ 期限までの月数（今月と期限の月を含む）。貯金後の残りから確保する
- お金の目標の毎月の貯金額 =（目標金額 − 貯まっている額）÷ 今月から目標日の月までの月数。毎月の貯金・積立から確保する
- 貯金の目標額（自動）= 計画に含めた未達成のお金の目標の目標金額の合計。期限はいちばん遅い目標日
- 収入・固定費・変動費・毎月の貯金は、項目の合計を使う
- 将来の残高 = 前月の残高 + 運用益（年利 ÷ 12 の月複利、初期値 0%）+ 毎月の積立 + その月の臨時収支
- 換算: 1年 = 12か月 = 52週 = 365日
- 実績で記録のない項目は 0 と見なさない。傾向は記録が十分あるときだけ単純な平均で示す

## フォルダの構成

```
src/
  engine/     計算エンジン（画面から独立した純粋な関数とテスト）
    time.ts       calculateWeeklyTimeBudget  … 週の時間配分
    money.ts      calculateMonthlyBalance / projectSavings … 収支と将来の残高
    goals.ts      calculateGoalFeasibility … 目標が時間・予算に収まるか
    scenarios.ts  cloneScenario / diffScenarios / compareScenarios … シナリオ
    deviation.ts  calculatePlanDeviation / summarizeTrend … 計画と実績の差
    units.ts      単位換算と日付
  data/       データの型・IndexedDB 保存・バックアップの検証・サンプル
  ui/         共通の部品（入力欄、シート、グラフ、168マス）
  screens/    5つの画面
public/       アイコン・PWA の設定・Service Worker
```

使っているもの: React 19 / TypeScript / Vite / Vitest。グラフは外部ライブラリを使わず SVG で描いています。
